# E2-S3 – Recherchelauf anlegen: Übergabe

Branch: story/E2-S3-lauf-anlegen (baut auf story/E1-S2-vorfuehrdatum auf) · Datum: 19.11.2026 · Ergebnis: Fertig

## Was gebaut wurde
`POST /api/v1/agent/laeufe` (nur mit Agenten-Schlüssel). Das Format steht als Zod-Schema in `src/gemeinsam/lauf.ts` und gilt später auch für die Ergebnisdatei. Der Dienst `legeLaufAn()` prüft jeden Vorschlag einzeln, weist Vorschläge ohne Firmen- oder Personennamen mit Feld und Meldung zurück, legt die übrigen im Zustand »zu_pruefen« an und speichert die gelieferten Daten unverändert als JSON am Vorschlag. Unbekannte Felder (z. B. ein mitgeschickter Zustand) werden verworfen. Ein zweiter ausgeführter Lauf am selben Tag wird mit 409 abgelehnt. Der Beispiel-Lauf mit den vier Vorschlägen aus Konzept 1.2 liegt in `src/simulator/beispiel-lauf.json`.

## So prüft man es von Hand
```
npm run reset && npm run dev
curl -s -X POST localhost:3000/api/v1/agent/laeufe \
  -H "Authorization: Bearer demo-agent-schluessel-nur-fuer-den-prototyp" \
  -H "content-type: application/json" --data @src/simulator/beispiel-lauf.json
```
Antwort `{"lauf_id":5,"angelegt":4,"zurueckgewiesen":[]}`; ein zweiter Aufruf am selben Tag liefert 409 `bereits_gelaufen`. Anzeigen lässt sich der Lauf erst mit E3-S1.

## Abweichungen und neue Abhängigkeiten
- Keine neuen Abhängigkeiten (Zod war schon da).
- `src/simulator/beispiel-lauf.json` gehört nach Architektur zum Agenten-Simulator (E1-S3); er liegt schon hier, weil die Tests ihn brauchen.
