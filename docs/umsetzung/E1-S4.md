# E1-S4 – Echtbetrieb neben dem Vorführbestand: Übergabe

Branch: story/E1-S4-echtbetrieb (baut auf story/E2-S5-upload auf) · Datum: 19.11.2026 · Ergebnis: Fertig

Neue Wegbereiter-Story aus Konzept 1.3 (Marcos Wunsch nach echten Daten, 19.11.2026).

## Was gebaut wurde
`npm run echt` (`scripts/echt.mjs`, auch unter Windows): richtet mit `src/server/echt.ts` die Datenbank `data/echt.sqlite` ein, falls sie noch nicht eingerichtet ist, und startet dann `npm run dev` mit `DATABASE_PATH=./data/echt.sqlite` und `COCKPIT_DEMO=0`. Der Dienst `richteEchtbetriebEin()` lädt nur in eine leere Datenbank den Grundbestand (`ladeGrundbestand` in `daten/startdaten.ts`): Rechercheprofil, die fünf Firmen des Startbestands der Sperrliste (mit dem Datum des ersten Starts), Signatur; dazu den Agenten-Schlüssel aus `COCKPIT_AGENT_KEY`. Keine Firmen, Kontakte, Läufe, Sperrzeiten, kein Vorführdatum. Ohne Vorführmodus gibt es weder `/api/v1/sim` noch die Vorführleiste; die Uhr nimmt das echte Datum.

`npm run reset` bricht ab, wenn `DATABASE_PATH` auf `echt.sqlite` (oder `ECHT_DATABASE_PATH`) zeigt. Die Tests nutzen eigene Dateien (`data/test.sqlite`, `data/test-echt.sqlite`).

Nebenbei: Der Upload entfernt ein BOM am Dateianfang (Dateien aus Windows-Editoren).

## So prüft man es von Hand
Im Projektordner `npm run echt`, dann http://localhost:5173: Eingangskorb leer, Kontakte leer, Einstellungen mit fünf Sperreinträgen, keine gelbe Vorführleiste. Beenden mit Strg+C; beim nächsten `npm run echt` ist alles noch da.

## Hinweise
- Den Vorführbestand gibt es weiter mit `npm run dev`; beide laufen nicht gleichzeitig (gleiche Ports).
- Eine Sicherung von `data/echt.sqlite` ist nicht Teil der Story (»Nicht enthalten«); Kopieren der Datei bei beendetem Cockpit genügt.
