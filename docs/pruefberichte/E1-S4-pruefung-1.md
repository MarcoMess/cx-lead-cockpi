### Windows (PowerShell, `npm.cmd`)
Auf echtem Windows habe ich nicht geprüft. Nach dem Code halte ich das Skript dort für plausibel lauffähig:
- `spawnSync('npx tsx src/server/echt.ts', { shell: true })` und `spawn('npm run dev', { shell: true })` laufen unter Windows über `cmd.exe`. Dort werden `npx.cmd` und `npm.cmd` gefunden. Ohne `shell: true` würde Node (seit 18.20/20.12) `.cmd`-Dateien gar nicht starten. Das ist also richtig gelöst.
- Die Umgebung wird als vollständige Kopie von `process.env` weitergegeben. `./data/echt.sqlite` mit Schrägstrich funktioniert unter Windows in Node. Die Sperre in `reset.ts` erkennt `\` und Groß- und Kleinschreibung. Das passt zu Windows-Pfaden und zum Dateisystem, das Groß- und Kleinschreibung nicht unterscheidet.
- Strg+C erreicht unter Windows alle Prozesse der Konsole. `concurrently -k` beendet Server und Vite. Bei `npm.cmd` kann die übliche Frage »Batchvorgang abbrechen (J/N)?« kommen. Das ist nur kosmetisch und bei `npm run dev` genauso.
- In PowerShell setzt man eine abweichende Datei mit `$env:ECHT_DATABASE_PATH='…'; npm run echt`. Das ist nirgends beschrieben, für Marco aber auch nicht nötig.
